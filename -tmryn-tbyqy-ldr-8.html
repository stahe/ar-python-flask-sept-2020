    25. تمرين تطبيقي: الإصدار 8

    25.1. مقدمة

    سنقوم بكتابة تطبيق عميل/خادم جديد. الجديد في الخادم هو أنه سيدير جلسة عمل. بدلاً من وضع بيانات إدارة الضرائب في كائن ذي نطاق [application]، سنضعها في كائن ذي نطاق [session]. وبذلك، تتراجع أداء الكود. عندما يمكن مشاركة كائن ما للقراءة فقط من قبل جميع المستخدمين، يُفضل جعله كائنًا بنطاق [application] بدلاً من نطاق [session]. ونكسب على الأقل في عرض النطاق الترددي لأننا نخفض بذلك حجم ملف تعريف الارتباط الخاص بالجلسة. لكننا نريد عرض تطبيق عميل/خادم حيث يتبادل العميل والخادم ملف تعريف ارتباط خاص بالجلسة.

    لا تتغير بنية التطبيق:

    25.3.1.1. الفئة [ImpôtsDaoWithHttpSession]

    يتم تنفيذ الطبقة [dao] بواسطة الفئة [ImpôtsDaoWithHttpSession] التالية:

    
# الاستيرادات

import requests
from flask_api import status
from myutils import decode_flask_session

from AbstractImpôtsDao import AbstractImpôtsDao
from AdminData import AdminData
from ImpôtsError import ImpôtsError
from InterfaceImpôtsMétier import InterfaceImpôtsMétier
from TaxPayer import TaxPayer


class ImpôtsDaoWithHttpSession(AbstractImpôtsDao, InterfaceImpôtsMétier):

    # المنشئ
    def __init__(self, config: dict):
        # تهيئة العنصر الأصلي
        AbstractImpôtsDao.__init__(self, config)
        # تخزين عناصر التكوين
        # التكوين العام
        self.__config = config
        # الخادم
        self.__config_server = config["server"]
        # وضع التصحيح
        self.__debug = config["debug"]
        # مسجل
        self.__logger = None
        # ملفات تعريف الارتباط
        self.__cookies = None

    # طريقة غير مستخدمة
    def get_admindata(self) -> AdminData:
        pass

    # حساب الضريبة
    def calculate_tax(self, taxpayer: TaxPayer, admindata: AdminData = None):
        # السماح بترحيل الاستثناءات
        # معلمات get
        params = {"marié": taxpayer.marié, "enfants": taxpayer.enfants, "salaire": taxpayer.salaire}
        # تسجيل الدخول باستخدام المصادقة Auth Basic؟
        if self.__config_server['authBasic']:
            response = requests.get(
                # URL للخادم المستعلم عنه
                self.__config_server['urlServer'],
                # معلمات URL
                params=params,
                # المصادقة الأساسية
                auth=(
                    self.__config_server["user"]["login"],
                    self.__config_server["user"]["password"]),
                cookies=self.__cookies)

        else:
            # تسجيل الدخول بدون مصادقة Auth Basic
            response = requests.get(self.__config_server['urlServer'], params=params, cookies=self.__cookies)
        # يتم استرداد ملفات تعريف الارتباط من الرد إن وجدت
        if response.cookies:
            self.__cookies = response.cookies
            # يتم استرداد ملف تعريف الارتباط الخاص بالجلسة
            session_cookie = response.cookies.get('session')
            # يتم فك تشفيره لتسجيل الدخول
            if session_cookie:
                # أداة تسجيل الدخول
                if not self.__logger:
                    self.__logger = self.__config['logger']
                # يتم تسجيل الدخول
                self.__logger.write(f"cookie de session={decode_flask_session(session_cookie)}\n")

        # وضع التصحيح؟
        if self.__debug:
            # مسجل
            if not self.__logger:
                self.__logger = self.__config['logger']
            # يتم التسجيل
            self.__logger.write(f"{response.text}\n")
        # رمز حالة الاستجابة HTTP
        status_code = response.status_code
        # يتم وضع الرد jSON في قاموس
        résultat = response.json()
        # خطأ إذا كان رمز الحالة مختلفًا عن 200 OK
        if status_code != status.HTTP_200_OK:
            # نعلم أن الأخطاء قد تم ربطها بالمفتاح [erreurs] الخاص بالاستجابة
            raise ImpôtsError(87, résultat['réponse']['erreurs'])
        # من المعروف أن النتيجة قد ارتبطت بالمفتاح [result] في الرد
        # يتم تعديل معلمة الإدخال باستخدام هذه النتيجة
        taxpayer.fromdict(résultat["réponse"]["result"])

    يجب أن نتذكر الآن أن طبقة [dao] سيتم تنفيذها في وقت واحد بواسطة عدة خيوط. لذا، يجب فحص جميع خصائص مثيل الفئة والتأكد مما إذا كان الوصول المتزامن إلى هذه الخصائص يمثل مشكلة. هنا أضفنا الخاصية [self.__cookies]، في السطر 30. يتم تعديل هذه الخاصية في السطر 59. وبالتالي، لدينا وصول للكتابة إلى بيانات مشتركة بين جميع الخيوط. لكن هذا الوصول يمثل مشكلة: فكل خيط يمثل عميلاً معيناً له ملف تعريف ارتباط جلسة خاص به. ففي الواقع، تحتوي ملفات تعريف الارتباط هذه على رقم عميل (=خيط) فريد لكل عميل. وإذا لم نتخذ أي إجراء، فقد يقوم الخيط T2 بالكتابة فوق ملفات تعريف الارتباط الخاصة بالخيط T1.

    لقد رأينا بالفعل طريقة لإدارة هذه المشكلة: يمكننا إنشاء مفاتيح مختلفة لكل مؤشر ترابط في الملف [config] الذي يتم تمريره كمعلمة إلى المنشئ (السطر 17). يمكننا، على سبيل المثال، استخدام اسم مؤشر الترابط كمفتاح:

    • في السطر 59، يمكن كتابة: 
    
config[thread_name][‘cookies’]=cookies
    • في السطر 52، يمكننا عندئذٍ كتابة: 
    
cookies=config[thread_name][‘cookies’]

    سنستخدم هنا تقنية مختلفة: سيكون لكل مؤشر ترابط (=عميل) طبقة [dao] خاصة به. وبذلك، لن يمثل السطر 59 مشكلة بعد الآن لأن ملفات تعريف الارتباط المستخدمة ستكون خاصة بعميل واحد فقط.

    لهذا الغرض، سنقوم بإنشاء فئة جديدة [ImpôtsDaoWithHttpSessionFactory].

    25.3.1.2. وظيفة فك تشفير جلسة Flask

    يتم تعريف الدالة [decode_flask_session] في البرنامج النصي [myutils]:

    لقد درسنا بالفعل البرنامج النصي |myutils|. هذا البرنامج النصي هو وحدة نمطية على مستوى الجهاز يمكن للبرامج النصية المختلفة في هذه الدورة استيرادها باستخدام الأمر:

    import myutils

    يتم فيها تعريف الدالة [decode_flask_session] على النحو التالي:

    
def decode_flask_session(cookie: str) -> str:
    # المصدر: https://www.kirsle.net/wizards/flask-session.cgi
    compressed = False
    payload = cookie

    if payload.startswith('.'):
        compressed = True
        payload = payload[1:]

    data = payload.split(".")[0]

    data = base64_decode(data)
    if compressed:
        data = zlib.decompress(data)

    return data.decode("utf-8")
