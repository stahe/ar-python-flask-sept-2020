    37.1. إعادة تحديد موقع المكونات التابعة للتطبيق

    تجدر الإشارة إلى أن إدارة تبعيات التطبيق تتم في البرنامج النصي [syspath]. في الإصدار السابق، كان هذا البرنامج النصي كما يلي:

    
def configure(config: dict) -> dict:
    import os

    # مجلد هذا الملف
    script_dir = os.path.dirname(os.path.abspath(__file__))

    # مسار الجذر
    root_dir = "C:/Data/st-2020/dev/python/cours-2020/python3-flask-2020"

    # التبعيات
    absolute_dependencies = [
        # مجلدات المشروع
        # BaseEntity، MyException
        f"{root_dir}/classes/02/entities",
        # InterfaceImpôtsDao، InterfaceImpôtsMétier، InterfaceImpôtsUi
        f"{root_dir}/impots/v04/interfaces",
        # AbstractImpôtsdao، ImpôtsConsole, ImpôtsMétier
        f"{root_dir}/impots/v04/services",
        # ImpotsDaoWithAdminDataInDatabase
        f"{root_dir}/impots/v05/services",
        # AdminData، ImpôtsError، TaxPayer
        f"{root_dir}/impots/v04/entities",
        # الثوابت، الشرائح
        f"{root_dir}/impots/v05/entities",
        # مسجل، SendAdminMail
        f"{root_dir}/impots/http-servers/02/utilities",
        # مجلد البرنامج النصي الرئيسي
        script_dir,
        # التكوينات [database, layers, parameters, controllers, views]
        f"{script_dir}/../configs",
        # وحدات التحكم
        f"{script_dir}/../controllers",
        # الردود HTTP
        f"{script_dir}/../responses",
        # نماذج العروض
        f"{script_dir}/../models_for_views",
    ]

    # تحديد مسار النظام
    from myutils import set_syspath
    set_syspath(absolute_dependencies)

    # تحديد التكوين
    return {
        "root_dir": root_dir,
        "script_dir": script_dir
    }

    يجب إعادة تحديد مواقع جميع التبعيات التي يعتمد اسمها المطلق على المتغير [root_dir] في السطر 8، أي الأسطر من 13 إلى 26.

    سيكون النص البرمجي [syspath] في الإصدار الجديد كما يلي:

    
def configure(config: dict) -> dict:
    import os

    # مجلد هذا الملف
    script_dir = os.path.dirname(os.path.abspath(__file__))

    # التبعيات
    absolute_dependencies = [
        # كيانات التطبيق
        f"{script_dir}/../entities",
        # الطبقة [dao]
        f"{script_dir}/../layers/dao",
        # طبقة [métier]
        f"{script_dir}/../layers/métier",
        # الأدوات المساعدة
        f"{script_dir}/../utilities",
        # مجلد البرنامج النصي الرئيسي
        script_dir,
        # التكوينات [database, layers, parameters, controllers, views]
        f"{script_dir}/../configs",
        # وحدات التحكم
        f"{script_dir}/../controllers",
        # الردود HTTP
        f"{script_dir}/../responses",
        # نماذج العروض
        f"{script_dir}/../models_for_views",
    ]

    # يتم تعيين مسار النظام
    import sys
    # إضافة التبعيات المطلقة للمشروع
    for directory in absolute_dependencies:
        # التحقق من وجود المجلد
        existe = os.path.exists(directory) and os.path.isdir(directory)
        if not existe:
            # إخطار المطور
            raise BaseException(f"[set_syspath] le dossier du Python Path [{directory}] n'existe pas")
        else:
            # يتم إدراج المجلد في بداية مسار النظام
            sys.path.insert(0, directory)

    # يتم إجراء التهيئة
    return {
        "script_dir": script_dir,
    }
    • الأسطر 8-27: أصبحت جميع التبعيات الآن مرتبطة بالمتغير [script_dir] في السطر 5؛
    • الأسطر 42-45: اختفى المتغير [root_dir] من تكوين syspath؛
    • السطر 10: كيانات التطبيق موجودة في المجلد [entities] [1]؛
    • السطر 12: الطبقة [dao] موجودة في المجلد [layers/dao] [2]؛
    • السطر 14: الطبقة [métier] موجودة في المجلد [layers/métier] [2]؛
    • السطر 16: الأدوات المساعدة [Logger, SendMail] موجودة في المجلد [utilities] [3]؛
    • الأسطر 29-40: يتم حساب مسار Python للتطبيق دون استيراد الوحدة النمطية [myutils]؛

    37.3. نقل تطبيق Python / Flask إلى خادم Apache / Windows

    37.3.1. المصادر

    لإجراء نقل تطبيق Flask إلى Apache / Windows، اضطررت إلى البحث على الإنترنت. إليكم الرابط الذي ساعدني على البدء: [https://medium.com/@madumalt/flask-app-deployment-in-windows-apache-server-mod-wsgi-82e1cfeeb2ed]؛

    استخدمت المعلومات الواردة في هذا الرابط باستثناء إعدادات خادم Apache. بالنسبة لهذه الإعدادات، استخدمت مثالًا لإعداد خادم Apache من Laragon.

    37.3.2. تثبيت وحدة Python mod_wsgi

    كان تطبيق Python / Flask الذي قمنا بتطويره يستخدم خادم WSGI (Web Server Gateway Interface) [werkzeug] المرفق مع Flask. يتم وصف هذا الخادم |هنا|. يصف الرابط [https://www.fullstackpython.com/wsgi-servers.html] كيفية عمل خوادم WSGI. توجد |خوادم WSGI| مختلفة. أحدها هو خادم Apache الذي يعمل في وضع WSGI. وهذا هو الحل الذي تم اعتماده هنا لأن Laragon، الذي قمنا بتثبيته، يأتي مزودًا بخادم Apache.

    لكي يتمكن خادم Apache من استضافة تطبيق Python، يتعين علينا تثبيت وحدة Python [mod_wsgi]. يعد تثبيت هذه الوحدة أمرًا دقيقًا لأن عملية تجميع لغة C++ تتم أثناء التثبيت. ولنجاح التثبيت، يلزم وجود مُجمِّع Microsoft C++. ومن الحلول البسيطة تثبيت الإصدار الحالي من Visual Studio Community [https://visualstudio.microsoft.com/fr/vs/community/].

    وإذا لم تكن هناك حاجة إلى Visual Studio إلا من أجل [mod_wsgi]، فيمكن قصر التثبيت على بيئة C++:

    بمجرد تثبيت مُجمِّع C++، يتم تثبيت الوحدة النمطية [mod_wsgi] في محطة طرفية PyCharm:

    • عند [4]، يُشير Postman إلى أنه لم يتعرف على شهادة الأمان. يقوم بروتوكول HTTPS بإنشاء اتصال مشفر بين عميل الويب (وهو Postman في هذه الحالة) وخادم Apache. ويتم هذا الاتصال المشفر عن طريق شهادات يتم تبادلها بين العميل والخادم. ويقوم الخادم ببدء عملية إنشاء الاتصال المشفر عن طريق إرسال شهادة أمان إلى العميل. ولكي يقبل العميل هذه الشهادة، يجب أن تكون موقعة، أي مشتراة من شركات مخولة بإصدار شهادات الأمان. وعندما قمنا بتنشيط بروتوكول HTTPS الخاص بـ Laragon، قام Laragon بنفسه بإنشاء شهادة الأمان. وعندئذ يُقال إن الشهادة موقعة ذاتيًا. تصدر معظم برامج تصفح الويب تحذيرًا عند تلقي شهادة موقعة ذاتيًا. وهذا ما يفعله Postman في [4]. وعندئذٍ تقترح معظم برامج تصفح الويب تعطيل التحقق من شهادة الأمان المرسلة من الخادم. وهذا ما يقترحه Postman في [5]؛
